## 1. 背景与已确认语义

A 方案的服务端主体已落地：请求参数、`run_ground`、统一 `S` 旋转、落地、`gravity_aligned` 标记均已实现。本专项处理实施后的偏差与缺陷，不改动总体协议。

已确认的一条关键行为（与上游计划 5.4 一致，覆盖此前“无地面直接失败”的临时尝试）：

> 图片没有检测出地面时，服务端继续执行 SAM-3D 姿势推理，返回**相机锚定的 Figure 数值**，不做地面平面转换、不做重力对齐、也不落地；响应标记 `gravity_aligned=false`、`align_angle_deg` 为空，并附 warning。

原因：SAM-3D 推理在地面解析之后独立执行，地面缺失不应阻断姿势产出；只有“重力对齐后的世界/落地数值”不可用。

## 3. 修复方案

### S1 generic 支点统一

`generic_pose.pred_joint_coords` 是 MHR127 布局，索引 0 才是骨盆（见 `MHR_TO_SMPL` 中 SMPL 骨盆映射到 MHR 0）；当前用索引 1（左髋）作支点。

修复：
- 定义常量 `MHR_PELVIS_INDEX = 0`，`generic_pivot` 取 `generic_points[MHR_PELVIS_INDEX]`。
- 与主骨架支点交叉校验：若 `generic_pivot` 与 `joints[0]` 距离超过阈值（如 0.15 m），不抛错，改用 `pivot` 并追加 warning，避免个别异常输出放大错位。
- `pred_keypoints_3d` 与 `pred_joint_coords` 使用同一支点。

验收：同一 `S` 下，`generic_pose` 与 `joints_3d` 的骨盆点对齐后位置差仅为两套骨架本身的估计差，不随旋转角度放大。

### S2 无地面姿势契约固化

当前行为已按用户确认实现：`ground_transform is None` 时用 `_pose_vitpose_bbox` 生成 bbox，再走 SAM-3D，返回未对齐数值。

固化内容：
- bbox 决策表写入代码注释与测试：

| 条件 | bbox 来源 |
|---|---|
| 地面变换可用 | 人物 mask 框（现状） |
| 地面不可用，ViTPose 可用 | ViTPose 关键点框 |
| 地面不可用，ViTPose 不可用 | 人物 mask 框 |
| 两者都不可用 | 整图框 |

- body 增加 `bbox_source`（`mask` / `vitpose` / `full_image`），便于线上定位“姿势与参考项目不一致”属于哪条路径。
- `ground_mode="none"` 也走 ViTPose 框，与参考实现一致；需在计划中明确这是有意覆盖旧 `want_world=false` 行为。
- 无地面时不得出现 `world` 为 `ok` 的状态；`gravity_alignment.status` 取 `ground_unavailable` 或 `ground_error`，`error` 字段带原始失败原因。

验收：同一张无地面图片，服务端输出的 `joints_3d` 与 ImagePose_Resources 参考流程在容差内一致（同一 bbox、同一模型、同机运行）。

### S3 未开启对齐时的角度诊断

地面变换有效但 `align_gravity=false` 时，仍调用 `alignment_rotation(transform)` 取角度写入 `align_angle_deg`，同时保持 `gravity_aligned=false`，且绝不应用 `S`、不落地。

`gravity_alignment` 报告改为：

```json
{"status": "skipped", "reason": "disabled", "source": "ground", "angle_deg": 12.86, "error": null}
```

### S4 旋转退化与输入校验

- `up` 零范数：抛 `ValueError`，由现有 `except (ValueError, np.linalg.LinAlgError)` 转成 `gravity_aligned=false` + warning。
- `cos < -0.999999`（近似反向）视为无效地面方向，抛错降级，不构造叉积轴。
- 使用前校验 `R` 正交且 `det≈+1`（容差 1e-6），`t` 为 3 维有限值。
- 输出前断言 `S` 正交、`det≈+1`。

### S5 幂等与单次执行

- `apply_gravity_alignment` 入口检查 `body["gravity_alignment"]["applied"]`，已应用则抛 `ValueError("gravity alignment already applied")`。
- 成功后写入 `applied=true`、`pivot`、`dz`，供测试与诊断使用。
- 管线内只允许一处调用；后续新增调用点必须显式传入未对齐副本。

### S6 落地基准统一验证

需要先核实再改代码：

1. `joints_fig = camera_points_to_figure_frame(skeleton24(coords))` 是否已包含 `pred_cam_t` 平移；若未包含，`joints` 分支与 `mesh+cam_t` 分支的最低点不在同一相机基准。
2. `points_for_floor` 的 mesh 分支与 joints 分支必须使用同一基准；不一致时统一为“mesh 加 `cam_t`，joints 加同一 `cam_t` 后再比较”。
3. `dz` 只计算一次，所有位置载荷共用；`bip22`/`points_53` 的 cm 与 m 换算保持显式。
4. 保持 `bip22_joints[0]`、`points_53` root 行、`points_53_tsv` root 行的 `z=0` 且 xy 取对齐后骨盆 xy；落地只平移其余点。

### S7 元数据序列化收敛

采取服务端内收敛，不依赖外部库改动（`response_serialize.py` 属 ImagePose_Resources，插件专项再统一）：

- 删除 `poseResult` 下额外插入的 `<gravity_aligned>`、`<align_angle_deg>` 子节点，仅保留属性，避免消费方按固定子节点解析时异常。
- `align_angle_deg` 为 `None` 时不写该属性（当前写空字符串会让“无角度”和“角度为空串”不可区分）。
- `poseResult`、`csPose`、`targetPose` 三个节点的 `gravity_aligned` 全部取自 `body["gravity_aligned"]`，不允许各自推导。
- JSON 路径保持 body 直出；补测试确认三个结构中的字段一致。

### S8 状态枚举统一

| status | 含义 |
|---|---|
| `applied` | 已对齐并落地 |
| `skipped` + `reason=disabled` | 请求未开启对齐 |
| `ground_unavailable` | 请求开启对齐但地面未检出 |
| `ground_error` | 地面推理异常 |
| `invalid_direction` | 地面方向退化/反向 |
| `error` | 变换执行失败 |

`warnings` 文本统一以 `gravity alignment skipped: <reason>` 或 `gravity alignment unavailable: <error>` 开头。

### S9 测试补齐

新增 `ground_pipeline/test_gravity_alignment.py`（不依赖 GPU/模型，使用合成数据）：

1. 恒等：零倾角地面 → `S=I`，所有载荷数值不变。
2. 已知倾角 12.86°：各载荷全局旋转等于 `S·G`，位置满足 `S·(p-a)+a`，误差 < 1e-6。
3. 支点一致性：`generic_pose` 与 `joints_3d` 骨盆点在旋转后差值与旋转前一致。
4. 局部旋转不变：`local_rotation` 逐骨不变。
5. 幂等：二次调用抛错，数值不变。
6. 失败语义：无地面 → `gravity_aligned=false`、`angle=None`、warning 存在、`targetPose` 仍存在且数值未旋转。
7. `align_gravity=false` + 地面有效 → 数值不变、角度已报告、`gravity_aligned=false`。
8. 落地：mesh 与 joints 两种采样源下 `min_z≈0`，所有位置载荷共用同一 `dz`，`restProfile` 不变。
9. 单位：`cs` 的 cm/m 换算往返误差 < 1e-6；`points_53` root 行 `z=0`。
10. 序列化：XML 三个节点属性与 `body` 一致，`None` 角度不写属性，无重复子节点。
11. 退化：`up=0`、`up≈-e_z`、非正交 `R` 均被拒绝且不产生 NaN。

## 6. 验收标准

1. 12.86° 合成样例中，`joints_3d`、`keypoints_3d_coco17`、`generic_pose`、`retarget`、`cs` 全部按同一 `S` 旋转，支点各自为对应骨架骨盆，误差 < 1e-6。
2. `generic_pose` 与 `joints_3d` 不再因支点不同产生角度相关偏移。
3. 无地面请求：HTTP 200、`status=success`、`gravity_aligned=false`、`align_angle_deg` 缺省、warning 可读、`targetPose` 存在且为未旋转数值。
4. `align_gravity=false` 时任何载荷都不被旋转或落地，且地面有效时能读到角度。
5. 只落地一次：`min_z≈0`，root 行约束成立，重复调用被拒绝。
6. `restProfile` 对齐前后逐值不变。
7. XML 与 JSON 的 `gravity_aligned` 在 `poseResult`、`csPose`、`targetPose` 三处一致；`None` 角度不产生空属性或非法数值。
8. 全部测试可在无 GPU 环境运行。
