# 姿势服务 ↔ 3ds Max 插件对接契约（figure_v6）

> 适用版本：服务 `api_version=3`（`g:\UGit\Phy-SIC\ground_pipeline`）
> 插件端：`g:\UGit\QingGeTools\ImagePose_v2`（`PoseExtractor` / `cs_pose_xml.ms` / `cs_pose_apply.ms`）
> 本文描述**当前实现**的对接事实；与旧文档冲突处以本文为准。

---

## 1. 一句话契约

服务端把**顶层骨骼数据**统一到 `figure_v6`（+X 右、+Y 前、+Z 上），其中：

- 顶层 JSON / `retarget.position` → `figure_v6`、**米**；`ground_world_v1` 只出现在诊断块 `world` / `worldPose`；
- `cs`（`csPose` 载荷）→ 位置槽为**厘米**，其中相机中心与 `torso_length` 为**米**；`cs_pose_apply.ms` 把数值**直接当作 Max 系统单位**赋值（不做换算），因此该通道要求场景单位为 **1 unit = 1 cm**；
- `targetPose` 通道自带单位换算：位置为米，`cs_target_pose_apply.ms` 按 `units.SystemScale` 折成 Max 场景单位（见 8.1），场景设 cm 或 m 都正确；
- 插件**不做**相机系→Figure/世界系换基、**不读** `joints_3d`、`points_53`、`worldPose`；
- 插件只消费 `poseResult` / `csPose` / `targetPose` / `restProfile` / `overlay`，并自行完成「骨盆归零 + `figureBasis` + 位置推旋转 + 触地」。

## 2. 端点与握手

| 用途 | 方法 / 路径 | 说明 |
|---|---|---|
| 健康检查 | `GET /v2/pose/health` | 返回 `poseHealth` XML；插件要求 `api_version == 3` 且状态健康 |
| 推理 | `POST /v2/pose/single` | 请求 `poseRequest` XML，响应 `poseResponse` XML |
| 取消 | `POST /v2/pose/cancel` | `<poseCancel><request_id>…</request_id></poseCancel>` |

本机联调端口：`8001`（默认）或 `8004`。服务启动必须带 SAM3D 资产与 HF 离线环境变量，否则健康检查会长时间不通过。

## 3. 请求

插件实际发送的请求体（`pose_service_client.ms`）：

```xml
<poseRequest>
  <image_path>G:/UGit/Phy-SIC/images/man_exercise2.jpg</image_path>
  <request_id>pe_20261022_001</request_id>
  <want_overlay>true</want_overlay>
  <response_format>xml</response_format>
  <!-- 可选：自定义目标骨架包 -->
  <target_tpose_bundle>…</target_tpose_bundle>
  <target_fingerprint>sha256:…</target_fingerprint>
  <retarget_schema>auto</retarget_schema>
</poseRequest>
```

- `image_path` 失败时插件自动重试 `<image>` + Base64 data URI。
- `want_world` 默认 `true`，插件不显式传递即可。
- `image_path` 必须是**服务端可读**的路径（WSL 下为 `/mnt/g/...`，Windows 下为 `G:/...`，按部署方式区分）。

服务端完整字段见 [GROUND_SERVICE_API.md](./GROUND_SERVICE_API.md#请求字段)。

## 5. 坐标系与单位总表

| 数据 | 坐标系 | 单位 | 插件是否消费 |
|---|---|---|---|
| `keypoints_2d_coco17` | 图像像素 | px | 否（仅叠加图） |
| `camera` | `camera_x_right_y_down_z_forward` | m | 否 |
| `joints_3d` | `figure_v6` | m | 否 |
| `keypoints_3d_coco17` | 默认 SAM-3D 模型系；`keypoints_3d_coco17_frame=figure_v6` 时为 `figure_v6` | m | 否 |
| `bip22_joints` / `bip22_facing` | `figure_v6` | m | 否（与 `cs` 前 22 行同源 ×100） |
| `retarget.position` | `figure_v6`（`position_space=figure_v6_world`） | m | 是（`targetPose` 旋转叠加，不用 position） |
| `cs.pose_payload.data` | `figure_v6`，Figure 语义（块内无 `frame` / `unit`） | 位置行为 **cm**；`data[6]` 的 `center` / `torso_length` 为 **m** | 是 → `csPose` → Max 单位 |
| `cs.points_53` | `figure_v6`，`root` 行为骨盆 xy 投影 | **cm** | 否 |
| `world.*` | `ground_world_v1` | m | 否 |
| 无地面（`want_world=false` / `ground_mode=none` / 地面失败） | `figure_v6`（未对齐、相机锚定） | m（`cs` 为 cm） | 是（标签如实标注） |

`figure_v6`（顶层唯一坐标系）：

```text
FIGURE_P = [[-1,0,0],[0,0,1],[0,-1,0]]   # +X 右、+Y 前、+Z 上
p_fig = FIGURE_P · p_model
align_gravity=true 且对齐成功：绕骨盆支点旋转 S，再统一 z += dz（dz = -min_z）
```

`ground_world_v1`（仅 `world` / `worldPose` 诊断块）：

```text
p_world = R · p_cam + t          R/t 来自 ground 平面或 /v1/ground 透传
+Z 向上，地面平面 z = 0
落地：dz = -min_z_world（SAM3D 网格最低点，缺失时回退关节）
after snap：min_z_m ≈ 0，ground_snap.offset_m 记录 dz
```

> **不要**把顶层或 `world` 的绝对数值当真实米制人体尺寸。SAM3D 逐图输出的绝对尺度可能明显偏小（实测某图骨盆高度仅 12.2 cm、全高约 55.6 cm）。服务端目前只做落地平移，不做人体尺度归一。

## 6. `csPose` 八槽（插件唯一姿态来源）

`cs_response.py` 生成 `pose_payload.data`（8 槽），`response_serialize.build_cs_pose_element` 序列化为 XML 子节点：

| 槽（插件 1-based） | XML 节点 | 内容 | 单位/语义 |
|---|---|---|---|
| 1 `jointList` | `joints/p` | 目标骨架位置数组（≥22 点，含派生躯干点） | cm，`figure_v6`（Figure 解剖轴） |
| 2 `headList` | `headAxes/axis` | 头轴三联（右/上/前） | 无量纲方向 |
| 3 `footList` | `footNormals/n` | 左右脚法线 | 无量纲方向 |
| 4 `chest` | `chestRight` | 胸向右向量 | 无量纲方向 |
| 5 `pairList` | `torsoPairs/pair` | 躯干配对索引（`a` / `b`） | 0-based 整数 |
| 6 `handList` | `handFrames/hand/row` | 每手 3×3 轴 | 无量纲方向 |
| 7 `cameraSlot` | `camera` | `center` + `torso_length` / `fov` / `aspect` | `center` / `torso_length` 为**米**，`fov` 为度，`aspect` 无量纲 |
| 8 `validationPath` | `validationPath` | 校验文件名 | 字符串 |

规则：

- XML `index` 是 **0-based**，插件内部数组 `slot = index + 1`；
- 数值**不做单位缩放**，直接写入 Max；
- 槽 1 前 22 行与顶层 `bip22_joints * 100` 逐项一致（实测 maxdiff = 0.0），`[0]` 是 `Bip001` 根（骨盆 xy 投影、`z=0`），`[1]` 是 `Bip001 Pelvis`；
- 缺失点为 `null="true"`，插件侧为 `undefined`。

## 7. `targetPose`（`bip22_pose_v5`）

- `schema_version = bip22_pose_v5`，27 骨，`root` + `bones`；
- 每骨含 `global_rotation` / `local_rotation`（3×3，共轭换基）与 `position`（**head 语义**）；
- 属性：`frame="figure_v6"`、`position_space="figure_v6_world"`、`position_unit="meter"`、`unit="meter"`；
- 硬校验（序列化时）：
  - `position_semantic == "head"`；
  - `position_space ∈ {figure_v6_world, ground_world_v1}`（后者为兼容旧世界系载荷保留）；
  - `position_unit == "meter"`；
  - `root.position` 必须与 `bones[root.bone].position` 完全一致（1e-9）；
- 插件叠加时**只改旋转**，`root` / `position` 不写场景，避免破坏已完成的触地与高度约束。

## 8. 插件端的实际几何处理（对接关键）

`applyCharacterStudio`（[cs_pose_apply.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/cs_pose_apply.ms)）：

1. 快照目标 Biped 根的当前世界位置 `pasteRootPos`（paste in place）；
2. 进入 Figure Mode，用左右大腿水平投影建 `figRight`，`figUp = [0,0,1]`，`figFront = cross(figUp, figRight)`；
   `figureBasis = matrix3 figRight (-figFront) figUp`；
3. **骨盆归零**：`posePos[i] = (posePos[i] - posePos[pelvis]) * figureBasis`；
4. 位置推旋转：段方向 / 双段平面 / 骨盆与头多点评分；
5. 应用后恢复 `pasteRootPos`；高度按 `keepHeight` 取 `pasteRootPos.z` 或触地结果 `finalRootPos.z`；
   `SupportMode` / `FlatSupport` 负责触地、平脚、根 Z 微调。

由此可得两条结论：

- `cs` 里的**绝对平移（含世界系 x/y 与 z）不会被写入场景**；插件只用「相对骨盆的向量」推旋转；
- `root z=0` 只表达「世界系里已落地」，**不会**把角色搬到 Max 的 `z=0` 平面。角色落点由场景原有位置 + 插件触地设置决定。

### 8.1 单位与 Max 场景单位（cm / m）

3ds Max 的几何值只有「系统单位」一个量纲，`units.SystemScale` 表示 **1 英寸等于多少系统单位**；`cm_per_unit = 2.54 / units.SystemScale`。两条通道的处理不同：

| 通道 | 代码行为 | 对场景单位的要求 |
|---|---|---|
| `csPose` → `cs_pose_apply.ms` | 载荷数值直接作为系统单位赋给 Biped，**无任何换算** | 必须 **1 unit = 1 cm**（`units.SystemScale = 2.54`）；若场景为米，角色会被放大 100× |
| `targetPose` → `cs_target_pose_apply.ms` | [`figurePosToMax`](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/cs_target_pose_apply.ms#L526-L531)：`p_m × 100 ÷ cm_per_unit`，`cm_per_unit` 在 `load()` 时由场景实时读取 | 任意单位均正确：cm 场景 `cm_per_unit=1`，m 场景 `cm_per_unit=100` |

> 因此「插件不做米↔厘米换算」只对 `csPose` 通道成立；`targetPose` 是带单位换算的新通道。把该结论写进对接契约时必须带上通道限定，否则在米制场景下会被误读为「直接可用」。

「匹配图片视角」（[matchImageView](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/PoseExtractor.ms#L1376-L1391)）**不受场景单位影响**：

- 机位 `imageViewTM = pelvis + (center_m × figureBasis) × (场景躯干长度 / torso_length_m)`，比例因子把载荷的米折算成当前场景单位（cm 场景 ×100、m 场景 ×1）；
- FOV 以角度传入，`aspect` 无量纲，均与单位无关；
- 前提：槽 7 的 `center` 与 `torso_length` 必须同为米（当前服务满足）；若只有 `targetPose` 而没有 `csPose`，`imageViewTM` 不会生成，按钮会提示缺少相机数据。

## 9. 落地语义（必须理解）

- 仅在 `align_gravity=true` 且地面变换可用时落地，作用在 `figure_v6` 顶层数据上；
- 采样 mesh 顶点（缺失时回退 joints / keypoints）的最低 `z`，取 `dz = -min_z`，所有顶层位置 `z += dz`（`cs` 的厘米位置用 `dz*100`）；`gravity_alignment.dz_m` 记录该值；
- 落地是**刚体平移**：不改肢体相对关系、不改旋转、不改相机外参；
- `bip22_joints[0]`（root）的 `z` 恒为 0，`xy` 取骨盆 `xy`；
- `points_53` 中 `source_key == "root"` 的行同样取骨盆 `xy` + `z=0`；其余行做换基 + 落地平移；
- `world` 块是独立的诊断副本：在 `ground_world_v1` 里按世界系最低点重新落地，`world.ground_snap.offset_m` / `world.min_z_m` 只描述该副本，不代表顶层；`want_world=false` 时不生成。
- 无地面路径（`want_world=false` + `align_gravity=false` + `ground_mode=none`）**不落地**，顶层保持相机锚定的 `figure_v6` 原始位置。

## 10. 门禁与常见失败

插件「可应用」条件：

```text
status == "success"
AND root_missing != "true"
AND matchable != "false"
AND csPose 存在
```

| 现象 | 原因 | 处理 |
|---|---|---|
| `csPose missing` | 服务端未生成 CS 载荷 / 非 success | 看 `result.xml` 的 `error` 与 `matchability_reasons` |
| XML 500，`bip22_pose_v5 requires head positions …` | 序列化器校验白名单不含实际坐标系 | 校验需允许 `figure_v6_world` 与 `ground_world_v1`（`response_serialize.py` 的 `build_target_pose_element`） |
| `姿态关节数不足` | `csPose/joints` 少于 22 | 检查 `cs.pose_payload.data[0]` |
| 角色位置乱跳 | 误把 `targetPose.root` 当位移应用 | 保持「只改旋转」，根位移不应用 |
| 骨架悬空/陷地 | 插件 `SupportMode` / `keepHeight` 设置 | 在 Max 侧调整，服务端不再二次接地 |
| 人物明显偏矮/偏高 | SAM3D 逐图绝对尺度 | 下游按角色身高做缩放；服务端未做人体尺度归一 |

## 11. 已知差异与注意事项

1. **`csPose` 节点没有 `frame` / `unit` 属性**（只有 `version` / `method`）；JSON `cs` 块同样没有块级 `frame` / `unit`（只有 `pose_payload.frame` 等槽内字段）。单位按字段区分：位置槽为 cm，`camera` 的 `center` / `torso_length` 为 m，`bip22_joints` / `bip22_facing` / `bip22_height_m` 为 m。详见 [GROUND_SERVICE_API.md](./GROUND_SERVICE_API.md#单位与坐标系约定)。
2. `<worldPose>` 由 Phy-SIC 在 `poseResponse` 根末尾注入，**不在** `QingGeTools` 参考序列化器中；插件忽略该节点。
3. `retarget` 的 `frame` 恒为 `figure_v6`、`position_space` 恒为 `figure_v6_world`（与是否请求地面无关）；`ground_world_v1` 仅为旧载荷兼容保留在序列化白名单中。
4. 顶层（`figure_v6`）与 `world`（`ground_world_v1`）是**两套坐标系**，同名数值不可逐项比较；`world.*` 由顶层同一份几何换基而来，仅作诊断。客户端按 `figure_v6` 解析顶层即可，**不要**再自行换基。
5. `keypoints_3d_coco17` 默认是 SAM-3D 模型系（根相对、x 右 / y 下 / z 前）；只有 `align_gravity=true` 且对齐成功后才换基到 `figure_v6` 并写 `keypoints_3d_coco17_frame`。插件不消费该字段。
6. `camera` 始终是相机系，不随骨骼字段换基。

## 12. 对接自测清单

```bash
# 1) 健康检查（必须是 api_version=3 且 healthy）
curl -s http://127.0.0.1:8001/v2/pose/health

# 2) XML 推理（最小请求）
curl -s -X POST http://127.0.0.1:8001/v2/pose/single \
  -H "Content-Type: application/xml" \
  -d '<poseRequest><image_path>/mnt/g/UGit/Phy-SIC/images/man_exercise2.jpg</image_path><response_format>xml</response_format></poseRequest>' \
  -o response.xml

# 3) 关键断言
#    - poseResponse/@api_version == 3
#    - poseResult/status == success，matchable != false
#    - csPose/joints/p[@index="0"] 的 z == 0，前 22 行 == bip22_joints*100
#    - targetPose/@frame == figure_v6，position/@space == figure_v6_world
#    - worldPose/@frame == ground_world_v1，@status == ok，joints 整体 min ≈ 0（仅 want_world=true）
```

JSON 侧等价校验（`response_format=json` 或 `POST /v1/pose/single`）：

```python
assert body["joints_3d_frame"] == "figure_v6"
assert body["retarget"]["frame"] == "figure_v6"
assert body["retarget"]["position_space"] == "figure_v6_world"
assert "frame" not in body["cs"] and "unit" not in body["cs"]
assert body["cs"]["pose_payload"]["data"][0][0][2] == 0.0          # root z (cm)
assert body["cs"]["bip22_joints"][0][2] == 0.0                     # root z (m)
assert max(
    abs(a - b * 100)
    for a, b in zip(body["cs"]["pose_payload"]["data"][0][1], body["cs"]["bip22_joints"][1])
) < 1e-6                                                           # 骨盆行 == bip22_joints[1] × 100

# 仅 align_gravity=true 且对齐成功时成立
assert body["keypoints_3d_coco17_frame"] == "figure_v6"

# 仅 want_world=true 且地面可用时成立
assert body["world"]["frame"] == "ground_world_v1"
assert body["world"]["min_z_m"] < 1e-6
assert body["world"]["ground_snap"]["status"] == "applied"
```
