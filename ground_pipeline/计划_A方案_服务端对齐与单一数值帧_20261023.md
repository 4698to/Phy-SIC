# A 方案专项计划：服务端重力对齐与单一姿势数值帧

**日期：** 2026-10-23  
**状态：** 设计计划，待实现与验收  
**适用范围：** 姿势推理服务、ImagePose_v2 插件的姿势请求/响应与 `targetPose`、`csPose` 消费链路

## 1. 决策摘要

采用 A 方案：服务端根据请求参数完成重力对齐，响应只包含一份姿势数值；插件按既定坐标轴映射直接应用，不再根据 `worldPose` 计算换基、逆共轭或倾斜旋转。

三项约束：

1. 一次响应中所有姿势类数值必须处在同一姿势帧中，不并列返回“对齐版”和“未对齐版”。
2. 响应继续使用 `frame="figure_v6"` 作为载荷/数据族版本标识；是否重力对齐由 `gravity_aligned="true|false"` 表达。此后不能再仅凭 `frame` 推断 +Z 是否为重力向上。
3. 插件不负责判断姿势是否对齐重力，也不应用重力旋转；UI 开关仅作为请求参数传给服务端。

A 方案消除了当前服务端输出世界系姿势、插件再将其还原并额外旋正的双端变换链。服务端是唯一负责选择姿势数值方向的组件，插件只消费最终数值。

## 2. 范围与术语

本计划覆盖 `align_gravity` 请求参数、重力变换和落地处理、响应元数据、插件请求透传及插件端旧帧变换逻辑移除。`worldPose`、`ground_world_v1` 相关世界系换算可继续用于诊断或其他 API，但不得再决定 `targetPose` / `csPose` 中客户端实际应用的姿势数值。

- **Figure 帧**：`figure_v6` 的基础数值帧，定义来自 `FIGURE_P`。其中 +Z 为 Figure up，+X 为人物右，+Y 为人物前。
- **重力对齐**：把 Figure 帧中的世界向上方向映射到 Figure +Z 的刚性旋转；对齐成功时 `gravity_aligned=true`。
- **姿势数值帧**：本协议中用于直接应用的所有姿势位置、旋转和方向值。其 `frame` 标签仍写 `figure_v6`；+Z 的实际语义由 `gravity_aligned` 单独说明。
- **诊断世界系**：`ground_world_v1`，只供诊断、地面估计、可视化或既有世界系接口使用，不作为插件姿势变换的第二份数据源。

## 3. 现状与改造动因

服务端目前在 `want_world=true` 且地面变换成功时，调用 `apply_world_frames` 将关节、关键点、重定向骨架、通用姿势及 `cs` 等载荷替换为 `ground_world_v1` 数值；其中旋转通过 `q=R·FIGURE_Pᵀ` 共轭，位置则换基并加偏移。服务端的世界系变换细节见 [ground_retarget.py](file:///g:/UGit/Phy-SIC/ground_pipeline/ground_retarget.py#L496-L533) 和 [ground_retarget.py](file:///g:/UGit/Phy-SIC/ground_pipeline/ground_retarget.py#L722-L766)。

插件收到 `ground_world_v1` 后，会读取 `worldPose/transform`，构造换基矩阵，对每根骨执行逆共轭；重力对齐开启时再左乘倾斜修正 `S`。相关路径见 [cs_target_pose_apply.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/cs_target_pose_apply.ms#L165-L195)、[cs_target_pose_apply.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/cs_target_pose_apply.ms#L239-L338) 与 [cs_target_pose_apply.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/cs_target_pose_apply.ms#L742-L775)。这让服务端、序列化层、磁盘落盘层和插件共同参与姿势帧决策，也使响应中的数值可能处在不同坐标语义下。

插件当前没有把 UI 状态作为 `align_gravity` 发给服务端；`chkWorldAlign` 只改变 `PE_TargetPoseWorldAlign` 客户端全局变量，见 [PoseExtractor.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/PoseExtractor.ms#L1696-L1703)。请求 XML 则在 [pose_service_client.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/pose_service_client.ms#L426-L453) 构造。A 方案将开关的职责收敛到请求参数，不再由插件端参与数值变换。

## 4. 目标响应契约

### 4.1 请求参数

新增 XML/JSON 字段：

```xml
<align_gravity>true</align_gravity>
```

| 项 | 约定 |
|---|---|
| 名称 | `align_gravity` |
| 类型 | 布尔值；XML 接受服务端现有布尔解析器支持的字面值 |
| 插件行为 | 将 UI 开关状态原样传给服务端，不在插件本地应用旋转 |
| 缺省兼容 | 请求未提供时，服务端按 `want_world` 的解析值处理；维持旧客户端的默认行为 |
| 地面失败 | 本次姿势退化为未对齐数值，响应 `gravity_aligned=false` 并附 warning；不得静默宣称已对齐 |

计算地面所需的有效条件定义为 `run_ground = want_world || align_gravity`。因此，不请求世界系但请求重力对齐时，服务端仍需解析地面变换；是否构造完整 `world` 诊断块仍由 `want_world` 控制。

### 4.2 响应元数据

`poseResult`、`csPose` 和 `targetPose` 增加：

| 属性 | 类型 | 语义 |
|---|---|---|
| `gravity_aligned` | `true` / `false` | 此响应实际姿势数值是否已通过服务端重力旋转处理。只有有效地面变换且本次请求开启对齐时为 `true`。 |
| `align_angle_deg` | 有限数值或空值 | 计算出的 Figure up 到 +Z 的最小旋转角度。地面变换不可用时为空；有效变换可用但未请求对齐时仍可报告角度，便于诊断。 |
| `frame` | 固定 `figure_v6`（既有字段） | 标识数值载荷族/基础帧，不再承诺单独描述 up 轴语义。 |
| `unit` | 沿用当前各载荷单位 | `targetPose` 按现有约定；`csPose` 沿用现有单位约定，不因本次改造改变。 |

`worldPose`（若 `want_world=true`）继续描述地面估计及相机到 `ground_world_v1` 的诊断变换，不再是插件恢复姿势帧所必需的资源。插件不得依赖 `worldPose`、`target_frame.xml` 或其 `transform` 来应用 `targetPose`。

### 4.3 同帧要求

每个响应中，以下数组及载荷必须一起应用同一个 `S`，或一起保持未旋转：`joints_3d`、`keypoints_3d_coco17`、`generic_pose`、`retarget`（包括所有 `global_rotation`、`local_rotation`、`position`、`root.position`）、`cs`、`bip22_joints`、`points_53`、`points_53_tsv` 及 `csPose` 中的关节点、方向/法线/手部轴向。若某字段属于姿势数值、被插件或下游消费，就不能只改它的元数据而不改数值。

`world` / `worldPose` 保持诊断世界系语义，不纳入上述 Figure 姿势数值的一致性集合。`restProfile` 是静态目标骨架参考，不应用 `S`，也不随输入人物姿势旋转。

## 5. 数值变换定义

### 5.1 由地面变换构造 S

现有相机到世界变换为 `p_world = R·p_cam + t`；Figure 投影矩阵为 `P=FIGURE_P`。世界 +Z 在 Figure 帧中的方向为：

```text
u_fig = P · Rᵀ · e_z
```

归一化 `u_fig` 后，令 `c = u_fig·e_z`、`θ = acos(clamp(c,-1,1))`。若 `u_fig` 与 `e_z` 重合，`S=I`；若近似反向则作为不可用/异常地面方向处理并降级，避免叉积轴退化。其余情况：

```text
k = normalize(u_fig × e_z)
S = I + sin(θ)[k]× + (1-c)[k]×²
```

`S` 为 det=+1 的纯旋转，不使用 `q=R·Pᵀ` 作为旋转矩阵；`q` 的 det 为 -1，直接用作旋转会引入反射/镜像风险。该公式与插件现有 `buildTiltBasis` 数学定义一致，但 A 方案只在服务端保留实现。

### 5.2 姿势旋转、位置及方向

- 骨骼全局旋转：`G' = S·G_fig`。这是将当前插件 `#worldAlign` 的左乘行为移到服务端；禁止改成对全局旋转做 `S·G·Sᵀ`。
- 骨骼局部旋转：`local_rotation` 保持原值。对整个骨架统一左乘 `S` 不改变父子相对旋转；逐骨重算局部旋转反而会改变层级关系。
- 位置：`p' = S·(p-a)+a`，其中 `a` 是该载荷中表示骨盆的点。`targetPose` 使用其 root/骨盆位置作为支点；`cs` 及其他关节位置载荷使用各自同一骨架的骨盆位置。若服务端内部统一成米或厘米，先统一单位再算，输出时恢复该字段原有单位。
- 方向、法线和轴向：`d'=S·d`，方向不加位置偏移。
- 旋转与位置变换应作用于原始姿势帧数据；不得把世界系换基矩阵 `q` 与 `S` 混为一体。

插件 `cs_pose_apply.ms` 已通过源骨盆归一化后，将 Figure 帧关节点映射到 Figure basis；其 `figureBasis` +Z 定义为 up，位置相对 `sourcePelvis`，这是统一姿势帧可行的消费基础，见 [cs_pose_apply.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/cs_pose_apply.ms#L756-L766) 和 [cs_pose_apply.ms](file:///g:/UGit/QingGeTools/ImagePose_v2/plugin/cs_pose_apply.ms#L797-L805)。

### 5.3 落地顺序与 root 特例

重力对齐必须先于落地。对齐成功后，使用现有落地候选源优先级（SAM-3D mesh；不可用时 joints/keypoints）计算对齐后姿势的 `min_z`，沿 Figure +Z 统一平移 `dz=-min_z`。落地只在 `align_gravity=true` 且地面/采样有效时执行；`align_gravity=false` 时不得应用 `S`，也不得仅因 `want_world=true` 而把 Figure 姿势落地。地面估计失败时回退为未对齐且未落地。

落地平移要作用于全部绝对位置字段，不能移动方向、旋转或静态 `restProfile`。`cs` 中以骨盆为原点的相对位置在整体平移后保持不变。`points_53` / `points_53_tsv` 的 `root` 行继续以骨盆为 xy 来源并固定 `z=0`；其余点应用与对应骨架一致的对齐及落地处理。实现需复用现有 `landing_shift` 的采样源选择逻辑，避免网格、关节与响应数组选择不同基准；现有采样实现见 [ground_retarget.py](file:///g:/UGit/Phy-SIC/ground_pipeline/ground_retarget.py#L795-L853)。

> 实现前需针对位置支点、采样点单位及 root 行索引编写/核实测试。尤其要验证当前 `cs` 装配阶段已有的脚底对齐与 A 方案落地不会造成重复平移。

### 5.4 false 与失败语义

- `align_gravity=false`：`S=I`，不执行重力旋转，不执行基于重力方向的落地；响应仍为一份 `frame="figure_v6"` 姿势数据，元数据明确标记 false。
- `align_gravity=true` 且有效地面变换：应用 `S`，按 5.3 落地，标记 true。
- `align_gravity=true` 但地面推理失败/方向无效：不应用 `S`、不落地，标记 false，记录原因 warning；服务端按姿势请求的既有成功/错误策略返回，不伪造 angle 或 aligned 状态。
- 对齐失败与正常 `align_gravity=false` 必须可通过 warning/诊断字段区分。

## 7. 兼容与发布策略

| 服务端 | 插件端 | 预期行为与限制 |
|---|---|---|
| 新 A 方案 | 新插件 | 目标组合。插件透传开关，直接应用唯一 Figure 数值；状态/角度显示服务端实际结果。 |
| 新 A 方案 | 老插件 | 老插件识别 `figure_v6` 后不做 world 换基，直接应用服务端返回值；数值方向与新协议一致。老插件开关不再能控制服务端对齐，因为旧请求没有 `align_gravity`，服务端按 `want_world` 缺省兼容规则处理；发布说明需提示这一点。 |
| 老服务端 | 新插件 | 老服务端可能返回 `ground_world_v1` 数值。新插件不再执行恢复变换时，不能把此组合视为与新协议等价；需通过版本/能力检查拒绝、发出明确警告，或要求服务端先升级。不得静默把旧 world 值当作 `figure_v6`。 |
| 老服务端 | 老插件 | 保持原行为，不在此次变更范围内。 |

由于新插件移除对 `ground_world_v1` 姿势帧的客户端恢复能力，升级顺序建议为先升级服务端并确认响应 `frame="figure_v6"`，再升级插件；若部署不能保证同步，应增加协议能力标识或对不兼容 frame 明确失败，具体机制在实现评审时确定。

## 8. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| `frame="figure_v6"` 不再单独代表 up 轴 | 其他消费方只读 frame 时可能误判重力方向 | 文档和响应增加 `gravity_aligned`；检索并更新所有依赖 frame 判定的消费方；不认识新语义的系统不能猜测。 |
| 位置绕骨盆旋转 | 各载荷若选取不同支点，会出现骨架、关键点和 cs 相对错位 | 按载荷采用对应骨盆锚点；跨载荷对齐后做逐点一致性测试；cm/m 转换显式测试。 |
| 对齐/落地重复执行 | 脚底高度偏移或 root 与骨骼不重合 | 将变换封装为单次管线步骤，明确原始输入与派生输出；测试重复调用不发生二次旋转/平移，或通过流程结构保证只调用一次。 |
| 落地采样源不一致 | points、关节和 targetPose 最低点不一致 | 复用 mesh→joints/keypoints 的既有优先级；所有数组使用同一 `dz`。 |
| `q` 的 det=-1 | 把换基矩阵误当旋转会造成镜像或无效矩阵 | 姿势对齐只用 det=+1 的 `S`；增加 det、正交和左右侧检查。 |
| v5 序列化白名单 | 修改 `position_space` 可能触发序列化失败 | 继续用 `figure_v6_world` / `meter` 表达 head 位置空间；将 gravity aligned 作为独立元数据。 |
| 旧服务端与新插件混用 | 新插件无法按旧协议恢复 world 数值 | 协议能力检查或对 `ground_world_v1` 明确失败；按服务端优先的顺序升级。 |
| 地面估计错误或失败 | 姿势倾斜方向错误或请求退化 | 地面方向有效性检查；失败时 aligned=false、未落地并带 warning；大角度记录诊断，不隐式更换轴或镜像。 |

## 9. 分阶段实施

1. **契约与数学测试**：锁定请求缺省、响应标记、`S`、位置支点、落地顺序和失败行为；建立合成姿势测试覆盖零倾角、已知倾角（包括 12.86° 基准）、反向/退化方向与左右镜像检查。
2. **服务端变换与串联**：实现参数解析、ground 执行条件、单一数值变换及 world 诊断隔离；完成所有消费载荷同帧处理与序列化。
3. **插件透传与精简**：请求透传 UI 状态；删除客户端 frame 恢复/倾斜分支及不再需要的落盘依赖；更新状态和日志。
4. **联调与兼容验证**：先以新服务端配老插件验证，再上新插件；验证旧服务端被新插件明确识别并拒绝/告警，不静默错套。
5. **清理旧文档**：实现验收通过后，更新原统一姿势帧计划与插件端契约，清除与 A 方案矛盾的双帧和客户端变换约定。本专项计划通过评审前不直接覆盖原文档。

## 10. 验收标准

1. `align_gravity=true` 且地面有效时，响应所有姿势载荷的 `gravity_aligned=true`，插件不执行任何姿势帧旋转；地面 +Z 映射到 Figure +Z，S 为正交矩阵且 det≈1。
2. 已知 12.86° 倾角样例中，服务端各全局旋转的 `S·G_fig` 与旧插件 `#worldAlign` 左乘结果逐骨一致，误差在既有浮点容差内；不得以逆共轭 `q` 取代 `S`。
3. `align_gravity=false` 时，不应用 `S`、不执行重力落地；位置、方向与旋转数值与进入重力阶段前一致，`gravity_aligned=false`。
4. `align_gravity` 缺省请求的有效值等于 `want_world`；兼容默认行为有自动化测试覆盖。
5. `align_gravity=true` 地面失败时，主响应姿势未对齐、未落地，`gravity_aligned=false` 且存在可读 warning；所有数值有限。
6. 同一骨架中的 joints、keypoints、generic、retarget、cs、BIP22、points_53 和 csPose 同步旋转/平移；所有旋转矩阵保持正交，所有位置差值符合各自单位换算。
7. 落地成功时复用同一 `dz`，选定采样源最低点满足 z≈0；`points_53` root 行 z=0 且 xy 对应对齐/落地后的骨盆；不得产生二次落地。
8. `restProfile` 各骨矩阵在重力对齐前后逐值不变。
9. 服务端开启 `want_world` 时 `worldPose` 仍能诊断地面变换，但其存在与否不改变插件消费姿势数值。
10. 新插件应用服务端已对齐姿势后，骨骼应用数量、左右侧、朝向和 root 位置与服务端数值一致；不存在客户端 `frame_applied` 再变换、镜像或 NaN。
11. 新插件收到旧服务端 `ground_world_v1` 姿势载荷时有明确兼容失败/警告，不静默直接应用；新服务端 × 老插件的数值应用行为验证通过，并记录老开关失效边界。
12. 本地文件和 data URI 请求都能传递 UI 开关；`poseResult`、`csPose`、`targetPose` 的 `gravity_aligned` 状态一致。
